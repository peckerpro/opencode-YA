# v0.1 Plan - Local Agent Core

## 1. Milestone Goal

在 Linux 上交付一个最小但真实可运行的 YA：

1. 用户配置 MiniMax key 后可通过 CLI 发起流式对话。
2. 会话包含多轮上下文并能在进程重启后恢复。
3. 模型可调用注册表中的安全工具，agent loop 执行后继续回答。
4. loop 有步数、超时和失败边界。
5. `doctor` 能检查环境、配置和可写目录。
6. 任务通过共享 workspace 被领取、流转和审计。
7. 核心行为在没有真实 API key 时可用 fake provider 测试。
8. 每次 run 具有基础 Session Agent 身份和当前 session scope。

## 2. Milestone Non-goals

- 不实现 FastAPI、Web UI 或 TUI。
- 不实现 RAG、embedding、vector store、MinerU 或 markitdown。
- 不实现正式 Markdown memory 和 GitHub sync。
- 不实现 MCP client/server、Skill Hub 或 plugin marketplace。
- 不实现自动 multi-agent worker 调度。
- 不实现 scheduler/cron；该能力从 v0.2 开始。
- 不实现 Root Agent、跨 session 查看/控制、Project Team runtime。
- 不提供 shell、任意文件写入、删除或 Git push 工具。
- 不同时支持多个真实 LLM provider。

发现上述需求时，将其记录到 Backlog，不在当前任务中顺手实现。

## 3. Definition of Done

- YA-001 至 YA-008 全部为 Done。
- 项目在声明的 Python 版本和 Linux 环境可安装。
- `ya doctor`、`ya chat`、`ya run`、`ya tools list`、最小 `ya task` 命令通过验收。
- 单元和集成测试通过；外部 API 测试默认可跳过。
- 包含中文内容/路径的 UTF-8 测试通过。
- 没有真实 secret、`.env` 或本地数据库被提交。
- Session Agent 不能通过 application service 读取其他 session。
- 已生成 `reports/v0.1-alignment.md`。
- 所有偏差已分类；架构/范围偏差已进入 `DECISIONS.md`。
- 只有实际通过验收的产品功能进入 `CHANGELOG.md`。

建立可安装、可测试、可配置的 Python 项目基础，并固定 UTF-8、secret 和运行目录规则。

### 输入文档

- `src/ya/config/**`

- 提供统一日志初始化，默认不输出 secret。
- 所有 Python 文件读写显式 `encoding="utf-8"`。

### 验收标准

- `python -c "import ya"` 成功。
- 测试命令可运行且本任务测试全部通过。
- 仓库中没有真实 key、`.env` 或运行时数据。

### 不做

- 不连接 MiniMax。
- 不实现 agent loop、CLI 业务命令、数据库 schema 或 Web 服务。

## YA-002 - Provider Contract and MiniMax Streaming Adapter

### 目标

定义与供应商无关的 LLM 事件契约，并实现 MiniMax OpenAI-compatible streaming adapter。

### 输入文档

- `docs/ARCHITECTURE.md` 第 4.1 节
- MiniMax 官方 OpenAI-compatible 与 Chat Completions 文档
- YA-001 输出

### 文件范围

- `src/ya/ports/llm.py`
- `src/ya/domain/messages/**`
- `src/ya/adapters/llm/minimax.py`
- `tests/unit/adapters/llm/**`
- `tests/fixtures/llm/**`

### 实现要求

- domain message 和 stream event 不暴露 SDK 类型。
- 事件至少覆盖 text delta、tool call delta/completion、finish、usage、error。
- 支持配置 model、base URL、API key、timeout。
- 正确拼接分段 tool call arguments，并在完成时校验 JSON。
- provider HTTP/SDK 错误转换为 YA 可分类异常。
- 提供 fake provider 或 fixture 驱动 adapter 测试。
- 真实 API smoke test 必须显式 opt-in，默认测试不消耗额度。

### 测试要求

- 文本流事件顺序正确。
- 一个和多个 tool call 的分段参数可重建。
- malformed tool arguments 返回明确错误。
- timeout、认证失败、限流和普通 provider error 被归一化。
- usage/finish reason 缺失时有稳定行为。

### 验收标准

- application/domain 测试不需要安装或导入 MiniMax 专有类型。
- fixture stream 可得到完整文本和结构化 tool call。
- 没有 API key 时仅真实调用失败，fake 测试仍通过。
- adapter 不记录 API key 或完整认证 header。

### 不做

- 不实现其他真实 provider。
- 不在 agent loop 中执行工具。
- 不依赖 provider 的隐藏推理文本作为业务逻辑输入。

### 输出与交接

- provider protocol、MiniMax adapter、事件 fixtures 和测试。
- handoff 记录官方接口假设及任何兼容性差异。

## YA-003 - Session and Message Persistence

### 目标

持久化 session、message、run 和基础事件，使多轮上下文可恢复。

### 输入文档

- `docs/ARCHITECTURE.md` 第 9、16 节
- `docs/AGENT_ROLES_AND_PERMISSIONS.md` 的 Session Agent、Session 和基础 scope 章节
- YA-001 输出

### 文件范围

- `src/ya/ports/stores.py`
- `src/ya/domain/messages/**`
- `src/ya/adapters/stores/sqlite.py`
- `src/ya/adapters/stores/migrations/**`
- `tests/unit/adapters/stores/**`
- `tests/integration/session_store/**`

### 实现要求

- 定义 store port，不让 application 依赖 SQLite API。
- 保存 session、按序 message、run 状态和 agent/tool 事件。
- Session 保存 lifecycle、workspace/scope 和默认 Session Agent binding 的最小字段。
- run 保存 agent ID、role ID、owner、origin 和 session scope。
- 使用显式 migration/version 机制。
- 时间以 UTC ISO 8601 或等价无歧义格式保存。
- 写入具备事务边界，失败时不留下半条 message/tool result。
- 为后续 context window 策略保留 metadata，但 v0.1 不做复杂压缩。

### 测试要求

- 创建、追加、读取和恢复 session。
- 消息顺序稳定，含中文和 tool result 内容不乱码。
- transaction rollback 行为正确。
- migration 可在空数据库重复安全初始化。
- 不存在的 session 返回明确结果。
- 当前 Session Agent 请求其他 session 数据时被拒绝。

### 验收标准

- 关闭并重新打开 store 后，session 历史保持一致。
- 测试覆盖 user、assistant、tool 三类消息。
- 所有数据库测试使用临时目录，不污染 `~/.ya`。

### 不做

- 不实现 Markdown memory。
- 不实现向量检索。
- 不设计多节点数据库。

### 输出与交接

- store port、SQLite adapter、migration 和测试。
- handoff 说明 schema 版本与事务边界。

## YA-004 - Tool Registry and Safety Policy

### 目标

建立统一工具注册、schema 校验、权限判断和执行结果模型，并提供一个无副作用内置工具。

### 输入文档

- `docs/ARCHITECTURE.md` 第 5、15 节
- `docs/AGENT_ROLES_AND_PERMISSIONS.md` Capability 和 scope 章节
- YA-001 输出

### 文件范围

- `src/ya/ports/tools.py`
- `src/ya/domain/tools/**`
- `src/ya/tools/registry.py`
- `src/ya/tools/policy.py`
- `src/ya/tools/builtin/**`
- `tests/unit/tools/**`

### 实现要求

- 工具包含名称、描述、JSON schema、来源、risk、权限、timeout 和 enabled。
- 支持从有类型标注的 Python 函数生成 schema；不支持的标注明确失败。
- 注册时拒绝重复名称和非法 schema。
- 执行前完成 enabled、参数 schema、policy 和 timeout 检查。
- 定义 safe/guarded/dangerous 风险级别。
- 定义最小 `Capability`、scope 和 permission decision；禁止仅按 role 名称放行。
- v0.1 提供一个确定性、无写副作用的内置工具，例如 UTC 时间或受控系统信息。
- 结果统一表达 success/error，并为审计事件提供字段。

### 测试要求

- 注册、查询、禁用和重复名称。
- 合法/非法参数校验。
- policy 拒绝危险工具的默认行为。
- timeout 和 handler exception 归一化。
- 工具返回中文文本时保持 UTF-8。

### 验收标准

- `ToolRegistry` 可输出 provider 使用的 schema 列表。
- 未授权 dangerous 工具无法执行。
- tool handler 异常不会导致进程崩溃或泄露 traceback/secret 给模型。
- 至少一个内置 safe tool 的端到端单元测试通过。

### 不做

- 不提供 shell、任意文件写入、删除或 Git 工具。
- 不接入 MCP。
- 不实现持久化 circuit breaker；仅保留扩展字段。

### 输出与交接

- registry、policy、内置工具和测试。
- handoff 列出工具风险等级和默认 policy。

## YA-005 - Bounded Agent Loop

### 目标

组合 provider、store 和 tool registry，完成有界、可取消、可审计的基础 agent loop。

### 输入文档

- `docs/ARCHITECTURE.md` 第 4、5、16 节
- `docs/AGENT_ROLES_AND_PERMISSIONS.md`
- YA-002、YA-003、YA-004 输出

### 文件范围

- `src/ya/domain/agents/**`
- `src/ya/application/chat.py`
- `src/ya/application/runs.py`
- `tests/unit/agents/**`
- `tests/integration/agent_loop/**`

### 实现要求

- 接收 session、用户输入、provider、registry 和 run limits。
- 默认以 Session Agent 身份运行，并将 session scope 传给 tool/permission guard。
- 将 stream event 向调用方转发，同时持久化最终一致消息/事件。
- tool call 经过 registry 执行并将结果加入下一轮上下文。
- 支持 max steps、run timeout、取消和 repeated tool failure 终止。
- tool call ID 与 tool result 必须可关联。
- 中断后 run 标记为明确状态，不伪装完成。
- 基础策略为 ReAct 风格；不要求模型输出可见思维链。

### 测试要求

- 纯文本一轮回答。
- 多轮 session 上下文。
- 跨 session store/context 请求被 guard 拒绝。
- 一次工具调用后生成最终回答。
- 达到 max steps 后终止。
- 工具参数错误、工具失败、provider 失败和取消。
- partial stream 不写成成功的完整 assistant message。

### 验收标准

- fake provider 可脚本化驱动以上全部路径。
- 任意循环都有确定终止条件。
- run、message 和 tool event 可通过 correlation ID 关联。
- 核心测试无需网络。

### 不做

- 不实现 Plan-and-Execute、Reflection 或 multi-agent delegation。
- 不实现自动 context summarization。
- 不暴露 provider 隐藏推理内容。

### 输出与交接

- application service、agent loop 和集成测试。
- handoff 记录默认 limits 和终止状态。

## 5. v0.1 Agent Assignment Guidance

- Planner：细化任务卡但不得改变 milestone 边界；改变边界需 decision。
- Coding：一次只 claim 一个任务，按文件范围实现。
- Review：在进入 Testing 前检查依赖方向、安全和过度设计。
- Test：依据任务卡验证，不以“代码看起来正确”代替执行证据。
- Document：每个任务 Done 后归档 handoff；里程碑末生成 alignment。
- Coordinator：v0.1 由人工或 CLI task service 承担，不要求自动 worker runtime。

# v0.2 Plan - Knowledge, Web, Scheduler and Root Read

## Milestone Goal

在 v0.1 agent core 上增加 Markdown memory、文档解析/RAG、FastAPI/最小 Web UI、安全 scheduler，以及 Root Agent 的只读 session overview。

## Non-goals

- 不接入 community MCP server 或 Skill Hub。
- 不提供任意 shell/delete/Git push 的无人值守 job。
- 不实现完整 TUI。
- 不实现自动 multi-agent worker runtime。
- 不实现 Root Agent 的 send/spawn/pause/resume/archive/close。
- 不实现 project team 或跨 session 自动调度。
- 不实现完整音视频解析。

## Definition of Done

- V2-001 至 V2-009 全部 Done。
- Web 默认监听 `127.0.0.1`。
- memory 可脱离 vector index 读取并重建索引。
- scheduler 重启可恢复 job，且不会重复执行同一 occurrence。
- cron job 配置与日志无 secret 明文。
- Root Agent 可以按 privacy/scope 查看 session list/summary/search，但不能执行跨 session 写操作。
- Session Agent 的跨 session 读取被拒绝。
- 生成 `reports/v0.2-alignment.md`。

## V2-001 - Markdown Memory Store and Retrieval

### 目标

实现 Obsidian-compatible Markdown memory 的写入、读取、组织和基础检索。

### 输入

`docs/MEMORY.md`、`docs/ARCHITECTURE.md`、v0.1 store/config。

### 文件范围

`src/ya/domain/memory/**`、`src/ya/ports/stores.py`、`src/ya/adapters/memory/**`、相关测试。

### 实现要求

- frontmatter、tag、wikilink、daily/project/topic/episode 路径。
- Markdown 为事实源，ID 唯一，更新使用原子写入。
- full-text/metadata 基础检索。
- 中文文件名与正文使用 UTF-8。

### 测试要求

创建、更新、删除、检索、wikilink、非法 frontmatter、并发写入和中文路径。

### 验收标准

memory 文件可被 Obsidian 读取；索引不存在时仍能直接读取；无 secret 写入。

### 不做

GitHub push、embedding、自动事实推断。

### 输出

代码、测试、memory schema 和 handoff。

## V2-002 - Document Parser Adapters

### 目标

实现统一 parser port、MinerU adapter 和 markitdown fallback。

### 输入

`docs/ARCHITECTURE.md` 文档解析章节、MinerU/markitdown 官方接口。

### 文件范围

`src/ya/ports/parsers.py`、`src/ya/adapters/parsers/**`、fixtures 和测试。

### 实现要求

- 输出统一 block、source location、metadata、warning 和 parser version。
- MinerU 优先，失败时按策略 fallback。
- 支持 PDF、Markdown、Office、text 和 code 的能力检测。
- 不支持的媒体返回明确状态。

### 测试要求

fixture 解析、fallback、timeout、损坏文件、超限文件和中文内容。

### 验收标准

fallback 原因可见；业务层不依赖供应商类型；默认测试不要求真实 API。

### 不做

完整 image/video/audio parser。

### 输出

port、adapters、fixtures、能力矩阵和 handoff。

## V2-003 - RAG Ingest and Query

### 目标

完成 parse、chunk、embed、index、query 和 citation context 闭环。

### 输入

V2-001、V2-002、`docs/ARCHITECTURE.md` RAG 章节。

### 文件范围

`src/ya/application/rag.py`、`src/ya/ports/embeddings.py`、vector adapter、RAG domain 和测试。

### 实现要求

### 测试要求

### 验收标准

### 不做

### 输出

RAG service、adapter、测试和数据迁移说明。

## V2-006 - Scheduler Models, Store and Schedule Calculation

### 目标

建立持久化 cron job/run 模型和确定性 schedule calculation。

### 输入

`docs/SCHEDULER.md`、`docs/SECURITY.md`、v0.1 SQLite/config。

### 文件范围

`src/ya/scheduler/models.py`、`store.py`、`cron.py`、migration 和测试。

### 实现要求

- create/list/get/update/pause/resume/delete。
- cron、interval、daily、weekly、monthly 和 IANA timezone。
- occurrence key 唯一约束、atomic claim 和 lease。
- UTF-8 export 可选，但不含 resolved secret。
- job payload typed validation。

### 测试要求

next run、时区/DST、无效表达式、每月边界、重启恢复、并发 claim、中文 job 和 migration。

### 验收标准

两个 scheduler 实例不能 claim 同一 occurrence；pause/resume 结果确定；配置无 token。

### 不做

实际执行 agent/tool、GitHub/MCP job。

### 输出

models、store、parser、migration、测试和 schema 说明。

## V2-007 - Scheduler Runner, CLI and API

### 目标

执行低风险 job，并提供 CLI/API/Web 可用状态。

### 输入

V2-004、V2-006、`docs/SCHEDULER.md`。

### 文件范围

`src/ya/scheduler/runner.py`、`service.py`、scheduler application service、CLI/API 和测试。

### 实现要求

- 支持 prompt、安全 tool、daily review、task board check、workspace cleanup、report。
- timeout、cancel、有限 retry/backoff 和 misfire policy。
- max agent steps、child-run depth、自调用去重。
- job 固定 run-as role 和 scope；v0.2 不允许 scheduled Root Agent 跨 session action。
- 实现全部 `ya cron` 目标命令。
- 每个 run 写状态、attempt、summary 和 log ref。
- cleanup 仅操作 allowlisted tmp/expired artifact。

### 测试要求

成功、失败、timeout、retry、pause、manual run、misfire、restart、loop prevention、权限拒绝和日志脱敏。

### 验收标准

失败不无限重试；危险 tool 默认拒绝；CLI/API 状态一致；job 名称/结果 UTF-8 正常。

### 不做

Git push、外部 MCP、任意 shell/delete。

### 输出

service、runner、CLI/API、测试和运维说明。

## V2-008 - Session Registry and Root Read-only Overview

### 目标

实现 Root Agent 对所有允许 session 的只读 list、inspect summary、summarize 和 search，并为 Web/TUI 提供 overview API。

### 输入

`docs/AGENT_ROLES_AND_PERMISSIONS.md`、`docs/SECURITY.md`、V2-004。

### 文件范围

`src/ya/domain/sessions/**`、`src/ya/application/sessions.py`、`root.py`、session registry/store、Root CLI/API/UI 和测试。

### 实现要求

- 持久化 Session registry、status、privacy label、summary 和 last activity。
- 实现 `ya root sessions/inspect/summarize/summarize-all/search/status`。
- Root read 使用 `session.list/inspect/summarize/search` capability。
- 跨 session search 默认使用摘要/索引；原消息 inspect 按 privacy/scope policy。
- Session Agent 默认不注册这些 capability。
- Root read action 和 permission decision 写 audit。
- Web UI 提供 session overview、active status 和最近活动。
- Root overview 显示 memory、RAG、scheduler 和 Tool Registry 的只读健康/数量状态。

### 测试要求

session list/filter、summary 重建、search、private scope redaction、Session Agent 拒绝、Root allow/deny、audit 和中文标题。

### 验收标准

Root Agent 能查看允许 session 的只读状态；不能 send/spawn/lifecycle；Session Agent 不能读取其他 session；所有 root read 可追踪。

### 不做

跨 session instruction、session spawn/pause/resume/archive/close、project workspace 和 team。

### 输出

session registry、Root read service、CLI/API/UI、permission/audit 测试和 handoff。

# v0.4 Plan - Project Team Runtime, Permissions and Audit

## Milestone Goal

在 project workspace 内运行 Planner、Coding、Review、Test、Document 和 Coordinator team，并用统一 capability/scope/confirmation/audit 模型约束所有角色和 Root Agent。

## Non-goals

- 不实现跨 session 全自动优先级决策。
- 不让 scheduler 自动执行 Root Agent global orchestration。
- 不实现完整多模态 parser。
- 不提供无确认的通用 shell、删除或 Git push。

## Definition of Done

- V4-001 至 V4-008 全部 Done。
- 每个 run/task 有 owner、role、scope 和 permission decision。
- Project Agent 无法访问其他 project/session。
- Root Agent 无法绕过 deny、confirmation 或 audit。
- Team 能完成 Planner -> Coding -> Review -> Testing -> Document 闭环。
- 生成 `reports/v0.4-alignment.md`。

## V4-001 - Permission Models, Policy and Guard

### 目标

实现统一 Capability、Permission、Scope、Decision 和 Guard。

### 输入

`docs/AGENT_ROLES_AND_PERMISSIONS.md`、`docs/SECURITY.md`、现有 tool/scheduler/session policy。

### 文件范围

`src/ya/permissions/models.py`、`policy.py`、`guard.py`、migration/config 和测试。

### 实现要求

- `<resource>.<action>` capability。
- global/session/project/workspace/task/resource scope。
- deny precedence、role grant、resource policy、risk/origin 和 confirmation。
- permission expiry/revocation。
- tool、scheduler、session、project、MCP 和 Git 统一调用 guard。
- 禁止业务代码按 role 名称硬编码放行。

### 测试要求

allow/deny/confirm、scope intersection、expiry、revocation、origin、Root deny 和 concurrent policy update。

### 验收标准

同一请求在所有入口得到一致 decision；Root role 不能绕过 explicit deny；Session/Project scope isolation 通过。

### 不做

不实现 policy recommendation AI 或自动放权。

### 输出

模型、guard、policy loader、迁移、测试和 capability registry。

## V4-002 - Append-only Audit and Confirmation Service

### 目标

记录所有高危、跨 session、session lifecycle、project/team 和 permission action，并提供用户确认队列。

### 输入

V4-001、`docs/AGENT_ROLES_AND_PERMISSIONS.md` audit schema。

### 文件范围

`src/ya/permissions/audit.py`、confirmation application/API/store、CLI/Web/TUI 和测试。

### 实现要求

- append-only audit event。
- confirmation 支持 allow once、scope allow、temporary allow、deny。
- 绑定 capability、target、参数摘要、actor、expiry 和 policy rule。
- audit query/filter/export 使用 redaction。
- 普通 agent 不能修改/删除 audit。

### 测试要求

append、查询、tamper attempt、confirmation expiry/replay、敏感 instruction redaction、UTF-8 和 retention action audit。

### 验收标准

高危操作有完整 actor/target/decision/result 链；confirmation 不能被跨目标复用；无 secret 明文。

### 不做

不实现外部 SIEM。

### 输出

audit/confirmation service、interfaces、测试和 retention 说明。

## V4-003 - Project Role Profiles and Workspace Enforcement

### 目标

定义并实施 Planner、Coding、Review、Test、Document、Coordinator capability matrix。

### 输入

V4-001、project workspace、`AGENTS.md`。

### 文件范围

role profiles、workspace guard、file/tool policy、tests/fixtures。

### 实现要求

- Planner 默认不写代码。
- Coding 只写任务允许文件，一次一个 coding task。
- Review 默认只读；小修是独立 capability。
- Test 只运行 allowlisted command/workdir，危险命令确认。
- Document 只写项目文档/report，不能写产品代码或全局 memory。
- Coordinator 只管理 team scope。
- canonical path、symlink 和 project isolation。

### 测试要求

每个 role 的 allow/deny matrix、跨 project、路径 escape、memory write、code/doc boundary 和 permission override。

### 验收标准

角色默认权限符合文档；越界操作被拒绝并审计；显式授权只在目标 scope 生效。

### 不做

不运行 team dispatcher。

### 输出

role profiles、workspace enforcement、matrix tests 和配置说明。

## V4-004 - Team Coordinator and Agent Lifecycle

### 目标

在一个 project 内 spawn/stop worker、claim task、维护 lease/heartbeat 并控制返工循环。

### 输入

V4-002、V4-003、`docs/MULTI_AGENT_WORKFLOW.md`。

### 文件范围

team/coordinator domain、dispatcher、worker lifecycle、task event store 和测试。

### 实现要求

- team ID/project/workspace binding。
- role-specific spawn 和 max concurrency。
- atomic claim、lease、heartbeat、reclaim。
- Review/Testing 最多退回两轮，之后升级。
- crash/interruption 保留事件并恢复。
- Coordinator 不能执行 worker/root 的业务 capability。

### 测试要求

双 claim、worker crash、stale lease、duplicate task、retry loop、stop/resume team 和 project isolation。

### 验收标准

同一任务无双 owner；失联任务可恢复；循环有上限；Coordinator 越权被拒绝。

### 不做

不跨 project 自动调度。

### 输出

Coordinator runtime、lifecycle、事件、测试和 operator guide。

## V4-005 - Planner and Coding Flow

### 目标

实现 Planner 生成任务包并由 Coding Agent 严格按 scope 完成代码任务。

### 输入

V4-004、`AGENTS.md`、task package contract。

### 文件范围

Planner/Coding role adapters、prompt/output schemas、handoff 和测试。

### 实现要求

- Planner 输出完整 task package 和依赖。
- Coding 只领取 Ready task。
- 文件范围和 command allowlist 进入 guard context。
- 代码、测试命令和偏差形成 handoff。
- 不满足输入的任务退回 Planner，不自行扩大。

### 测试要求

有效/无效 task package、scope violation、并行不重叠任务、unknown file changes、handoff 和 cancellation。

### 验收标准

Coding 不能修改任务外文件；Planner 不能把模糊需求直接标 Ready；每次交接有证据。

### 不做

不自动通过 review/test。

### 输出

Planner/Coding flow、schemas、测试和示例。

## V4-006 - Review, Test and Document Flow

### 目标

完成独立 Review、Testing、Documentation gate 和 alignment/changelog 规则。

### 输入

V4-005、报告模板、`AGENTS.md`。

### 文件范围

Review/Test/Document role adapters、report projection、gate service 和测试。

### 实现要求

- Review findings severity、location 和 required action。
- Test 独立执行验收，不复用 Coding 的结论。
- Document 处理 alignment/decision/changelog。
- Review 默认只读，小修后必须重新 Testing。
- Done 需要 test evidence 和文档处理结论。

### 测试要求

阻塞 finding、无 finding、test fail/rework、两轮上限、document-only write、Changelog false-positive prevention。

### 验收标准

任务不能跳过 gate 进入 Done；Document 不能修改产品代码；失败与偏差保留。

### 不做

不自动接受高风险 finding。

### 输出

完整 stage flow、reports、gate tests 和 handoff。

## V4-007 - Root Team Control and Status Interfaces

### 目标

让 Root Agent 启动、暂停、恢复、停止 project team，并查看 active agents、task boards 和 team summary。

### 输入

V4-004、V4-006、Root Agent model。

### 文件范围

Root/team application service、CLI/API/TUI/Web 和测试。

### 实现要求

- `project.team.start/read/pause/resume/stop` capability。
- Root action 经过 confirmation/audit。
- Coordinator 只返回 project summary 和 report references。
- Root 可发送 team-level instruction，但 worker 仍按 role/project scope 执行。
- 显示 pending confirmation、blocked task、failed worker 和 last activity。

### 测试要求

start/stop、unauthorized Root policy、Session Agent rejection、team instruction、summary redaction 和 audit correlation。

### 验收标准

Root 能管理 team lifecycle，但不能让 worker 越权；所有 action 和结果可追踪。

### 不做

不根据全局状态自动启动 team。

### 输出

Root team interfaces、状态面板、测试和使用说明。

## V4-008 - v0.4 Integration, Security and Alignment

### 目标

验证 project team 闭环、角色隔离、Root/permission/audit 安全并完成发布对齐。

### 输入

V4-001 至 V4-007 的 handoff/review/test report。

### 文件范围

集成测试、范围内修复、文档、alignment、Decisions、Changelog。

### 实现要求

- 完整 Planner -> Coding -> Review -> Test -> Document flow。
- 跨 project/session 攻击和 role escalation 测试。
- Root deny/confirm/audit 测试。
- worker crash/recovery 和循环限制。
- secret/UTF-8/path safety 检查。

### 测试要求

端到端 team happy path、failure/rework、权限撤销、audit completeness 和 project isolation。

### 验收标准

Definition of Done 满足；没有静默提权；alignment 逐项给出证据。

### 不做

不提前实现 v0.5 autonomous orchestration。

### 输出

`reports/v0.4-alignment.md`、安全报告和发布结论。
